# 구간별 점수 가중치 (model 0.2)

## 요약

종합 자세 점수를 낼 때 4개 구간(스트라이드·트랜지션·스윙·팔로우)을 동등하게
더하던 것을, 구간별 가중치로 바꾼다.

    스윙 1.0  >  트랜지션 0.6  >  팔로우 0.3  =  스트라이드 0.3

## 왜 바꾸나

기존: `distance` = 전 구간 z 를 그냥 이어붙인 RMS → 네 구간이 1:1:1:1.
문제: 타격 결과와 무관한 준비/팔로우 동작이 스윙과 같은 비중으로 감점된다.

## 가중치 근거

근거의 성격을 구분해 둔다. 숫자를 데이터로 "증명"한 게 아니라, 코칭 판단을
주 근거로 하고 측정 신뢰도로 보강한 것이다.

### 스윙 = 1.0 (최고) — 코칭 근거

타격이 실제로 일어나는 구간(스윙 시작 → 임팩트). 공을 때리는 동작 그 자체이므로
기준과의 차이가 타격 결과에 가장 직접적이다. → 기준값.

### 트랜지션 = 0.6 — 코칭 근거

착지 후 스윙 직전 준비 동작. 힘을 싣는 연결 고리로 중요하지만 타격 그 자체는
아니므로 스윙 다음.

### 팔로우 = 0.3 (낮음) — 코칭 근거

임팩트 **이후** 동작이라 공에는 이미 영향을 주지 못한다. 자세가 기준과 달라도
타격 품질과 직접 연결되지 않는다.

### 스트라이드 = 0.3 (낮음) — 코칭 + 데이터 근거

- 코칭: 앞발 들기 ~ 착지의 준비 동작. 레그킥·노스트라이드 등 선수별 스타일
  자유도가 크다.
- 데이터: 프로 806개 중 구간 검출 성공 618개(77%)로 네 구간 중 최저
  (트랜지션 97%, 스윙 94%, 팔로우 98%). 경계(foot_lift/foot_plant)가 애매해
  구간 자체가 가장 불안정 → 이 구간의 감점을 그대로 믿기 어렵다.

> 참고: 스트라이드와 팔로우를 같은 0.3 으로 둔 이유는 서로 다르다
> (스트라이드 = 검출 불안정, 팔로우 = 임팩트 이후). 둘 다 "낮춘다"로 수렴한다.

## 근거로 쓰지 않은 것

- **"프로 자세 편차(std)"는 쓰지 않는다.** z-score 가 이미 그 std 로 나누므로
  (`z = (user − mean) / std`) 편차 큰 구간은 점수에 이미 반영돼 있다. 다시
  가중치로 쓰면 이중 보정이다.
- **구간 프레임 수(측정 해상도)도 쓰지 않는다.** 오히려 스트라이드가 가장 조밀하고
  (794ms ≈ 24프레임) 스윙이 가장 성기다(133ms ≈ 4프레임)라, 측정 신뢰도만 보면
  원하는 순서와 반대가 된다. 가중치는 측정 해상도가 아니라 코칭 중요도로 정한다.
- **타구 결과(안타/정타) 라벨이 생기면,** 구간 이탈 ↔ 결과 상관으로 가중치를
  통계적으로 유도할 수 있다. 현재는 라벨이 없어 코칭 판단을 쓴다.

## 적용 방식

    distance = sqrt( Σ_p w_p·Σ(z_p²) / Σ_p w_p·N_p )
      w_p = 구간 가중치, N_p = 그 구간의 유효 z 값 개수(지점 × 피처)

가중 개수로 나누므로 스케일은 기존과 비슷하게 유지된다.

세 곳에 같은 가중치를 일관 적용한다:

1. 종합 자세 거리 (`_overall_distance`)
2. 부위별 점수 (`overall()` 의 group_scores)
3. 점수 영향도(기여 비중, `_score_contributions`)

→ "distance² = 부위별 기여 합" 분해 성질은 그대로 유지된다.

## 기준선(typical_distance)은 재계산하지 않는다

80점 기준선 `typical_distance` 는 프로 스윙들이 평균 곡선에서 떨어진 거리의
중앙값이다(`scripts/build_reference_model.py`). 원칙적으로는 같은 가중치로 다시
계산해 자기일관성을 맞춰야 하지만, **지금은 재계산하지 않는다.**

- 재빌드 불가: 현재 806 스윙 모델을 만든 구조화 `.npz` 스켈레톤이 로컬에 없다
  (로컬 데이터는 형식·규모가 다른 별도 세트다).
- 드리프트 미미: 프로는 정의상 기준 평균 근처라 모든 구간에서 z ≈ N(0,1),
  즉 평균 z² ≈ 1. 가중 평균을 내도 1 근처라 기준선은 거의 움직이지 않는다
  (현재 0.899 유지). 가중치가 실제로 바꾸는 것은 **사용자 스윙의 거리 분포**이지
  프로 기준선이 아니다.

`build_reference_model.py` 에도 같은 가중 RMS 를 넣어, 806 데이터가 복원되면
바로 일관 재빌드되도록 해 둔다. (TODO: 데이터 복원 시 가중 재빌드)

## 표시용 값에는 가중치를 적용하지 않는다

`frame_distances`(타임라인 곡선)·`worst_segment`·구간별 개별 점수·관절별 값은
화면 표시용이라 가중치 없이 그대로 둔다. 가중치는 "종합 점수" 산출에만 들어간다.
