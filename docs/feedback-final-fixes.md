# 피드백 최종 보완 및 비교·측정 계약 검수

2026-11-24 · 기준 origin/main `4e1ab160a90593eddcf462ead7aa7a96f9eebba3`

작업 공간: `swing-feedback-final-fixes`, 브랜치 `fix/feedback-contract-comparison`.
기존 `swing-feedback-concise-review`의 미커밋 간결화 변경을 패치로 가져온 뒤 이 작업 공간에서만 수정했다. 기존 갤러리, 평가 CSV, 원본 영상, 실험 worktree는 보존한다. 커밋·Push·PR·병합은 수행하지 않는다.

검토 갤러리: <http://127.0.0.1:9020/>. 실제 서비스 위젯을 import하는 독립 Flutter 진단 앱이며, 저장 JSON을 MockClient로 읽는다. 실제 로그인·운영 DB 연결이나 이번 작업의 신규 분석 결과가 아니다. 원본 6영상은 갤러리에서 재생하고 Flutter 종합·관절·구간 화면을 따로 열 수 있다.

진단 Flutter 화면은 영상/3D API를 제공하지 않으므로 영상 오류·빈 미리보기가 보일 수 있다. 이는 문구 검증 범위의 제한이며 실제 서비스 영상 삭제나 3D 회귀로 판정하지 않는다. 프로 사례에 표시되는 1970년 시각은 이전 진단 fixture의 대체값으로 실제 촬영일이 아니다. 이번 작업에서는 기존 fixture와 화면 비교 기준을 보존했다.

무게중심 위치는 현재 측정하지 않는다. 따라서 사용자가 제안한 취지는 유지하면서, 실제 측정처럼 들리는 표현을 원본에서 관찰할 수 있는 모습으로 바꿨다. 팔로우스루는 추정 임팩트부터 마무리까지이므로 ‘스윙을 마친 뒤’라고 단정하지 않는다. 스트라이드는 앞발을 들고 딛는 동안, 트랜지션은 착지 후 스윙 시작 전, 스윙은 스윙 중으로 문구를 분기한다. 선수·영상 ID 예외는 없다.

종합 기본 카드의 영상 확인과 선택적 연습은 각각 최대 2문장이다. 펼침 영역에는 기존의 자세한 확인 방법, 기준 그래프 접근 조건, 측정 한계, 선택적 재촬영 안내가 남는다. 골반을 수평으로 만들거나 보폭을 넓히는 처방은 추가하지 않았다. 실제 균형 문제나 팔 모양 확인 없이 연습의 타당성을 승인하지 않는다.

같은 6리포트의 종합 코칭 카드 기본 문구 합계는 최초 2,704자 → 이전 간결화 1,612자 → 이번 보완 **1,614자**다. 화면 라벨과 줄바꿈을 포함한 같은 방식의 집계이며 상세 펼침 문구는 제외한다. 이번 보완으로 2자 증가했고, 첫 확인 후보는 6건 모두 같다.

## 이전 스윙 비교

`GET /api/users/{user_id}/analyses/{analysis_id}/comparison`은 기존 인증·소유권 검사와 같은 사용자 직전 done 기록 선택을 유지한다. 반환 계약에 `comparable`, `comparison_reason`을 추가한다. 기존 필드는 유지한다.

- 이전 기록 없음: `has_previous=false`, `comparable=false`, `no_previous`.
- 이전 기록은 있으나 모델 버전·기준·계산 방식이 다름: `has_previous=true`, `comparable=false`, 원인 코드 반환. 이전 ID·시각은 유지하고 증감·부위/관절/구간 비교·비교 코칭은 반환하지 않는다.
- 버전은 같아도 당시 기준/계산 식별 정보가 없음: `comparison_metadata_missing`. 같은 기준이라고 추정하지 않는다.
- 검증된 같은 계약: `comparable=true`. 각 항목의 신뢰도·결측을 따로 검사하고 짧은 구간은 증감 판단에서 제외한다.
- 조회 오류: 이번 분석은 표시하되 이전 기록 상태를 확인하지 못했다는 안내. 첫 스윙이라고 단정하지 않는다.

새 실제 분석에만 `analysis_contract`를 추가한다. 모델 버전, 실제 기준 NPZ SHA-256, 점수·피처·이벤트 코드와 이벤트 가중치의 SHA-256, 측정 정의, 좌우타 정보를 기록한다. PR #91처럼 버전 문자열이 같아도 계산 소스가 달라지면 비교를 보류할 수 있다. SHA는 출처 확인용이며 정확도를 보장하지 않는다. 코드 서식만 바뀌어도 SHA가 달라지는 보수적 제한이 있다.

서로 다른 사용자 FPS만으로 비교를 막지는 않는다. 0.2 모델은 시간 길이를 사용한다. 촬영 조건 차이는 여전히 자동 검증할 수 없다는 안내를 유지한다.

과거 JSON에 현재 해시를 소급해서 넣지 않는다. 실제 친구 두 기록은 보존된 원본 기록에서 같은 사용자·이전 ID 연결을 확인했지만, 당시 기준/점수 계산 해시가 없어 증감 표시를 보류한다. 별도로 저장된 0.2.3 친구 분석도 열람할 수 있으나 0.2.2와 개선·악화 점수로 비교하지 않는다.

배포 시 새 분석부터 비교 계약이 저장되며, 이미 저장된 기록은 비교 보류가 늘어난다. 이전 결과를 복원하려면 당시 코드·기준 파일의 독립 기록이 필요하다. DB migration은 없다. 승인되지 않은 GPT 후보 공개, 비교 GET의 유료 생성, 승인 정책 변경은 없다.

## 매우 짧은 구간

중요: `user_frames=[start,end]`의 시간 길이는 `(end-start)/FPS`이고, `resample()`은 양 끝을 포함한다. ‘2프레임 길이’는 **2프레임 간격·관측값 3개**이며, 원본 관절이 2개뿐이라는 뜻이 아니다.

| 영상 | 구간 | 경계 | 프레임 간격 | 경계 포함 관측값 | 저장 시간 | 저장 신뢰도 |
|---|---|---|---:|---:|---:|---|
| 나승엽 | 착지 후 준비 | 8–10 | 2 | 3 | 65ms | medium |
| 박찬호 | 착지 후 준비 | 20–21 | 1 | 2 | 33ms | medium |
| 오재원 | 팔로우스루 | 125–126 | 1 | 2 | 17ms | medium |
| 윤동희 | 착지 후 준비 | 73–74 | 1 | 2 | 17ms | medium |
| 친구 1 | 착지 후 준비 | 25–27 | 2 | 3 | 67ms | high |

친구 2의 준비 구간은 3–26, 23프레임 간격이다. 기존 ‘3프레임’ 경고는 사용자 구간이 아니라 기준 스윙의 시간 길이를 사용자 FPS로 환산한 값이므로 구분해야 한다.

6영상 재디코딩 결과 프레임 수는 저장 분석과 일치하고 디코더 시각은 모두 순증가했다. 경계는 실제 프레임 범위 안에 있으며 저장 시간과 FPS 계산이 맞는다. 독립 컨테이너 PTS 도구와의 대조 및 실제 착지/스윙 시작의 사람 정답 검증은 하지 않았다.

FPS가 전부 같은 방식으로 일치한 것은 아니다. 나승엽은 저장/디코더 메타데이터 약 30.87FPS, 박찬호는 약 30.32FPS인 반면 두 영상의 디코더 시각 간격은 30FPS였다. 따라서 저장된 구간 시간과 디코더 시각 차이도 있다(나승엽 준비 구간 65ms 대 약 66.7ms). 친구 두 영상은 두 방식 모두 30FPS, 오재원·윤동희는 모두 60FPS였다. 이 작은 시간 차이가 1~2간격이라는 관측량 부족을 해소하지는 않는다. 모델의 기존 FPS 계산은 바꾸지 않았으며 컨테이너 PTS 대조는 별도 과제다.

코드상 이벤트는 손 속도·발목 움직임·사용 가능한 LSTM 앵커 등으로 결정된다. 서로 가까운 이벤트가 1~2간격 구간을 만들 수 있으며, 기존 구간 신뢰도는 영상 전체 신뢰도를 이어받는다. 짧은 곡선도 20개 지점으로 보간되므로 표시점 수를 관측량으로 해석하면 안 된다. 이 구조는 확인했지만 각 영상 경계가 실제로 잘못 검출됐다고 확정하지 않는다.

표시 정책은 **2간격 이하(관측값 2~3개)**이면 잘한 동작·교정 후보·연습·이전 대비 구간 증감을 보류한다. 구간 화면은 회색 ‘측정 확인 필요’, 관절 상세는 해당 구간 경고를 표시한다. 원래 점수·저장 신뢰도·이벤트는 유지한다. 3간격 이상이 정확하다는 보증은 아니며, 임계값은 보수적인 표시 조건이다.

6리포트의 첫 확인 후보는 유지된다. 다만 짧은 구간에 근거한 일부 ‘잘한 동작’은 제외되고 다음 유효 후보가 표시된다. 예를 들어 친구 1의 준비 구간 팔꿈치를 칭찬하던 항목은 제외된다. 이는 문구 수정의 수치 회귀가 아니라 요청한 짧은 구간 보류 정책의 의도된 변화다. 순위 계산식 `|z|`는 바꾸지 않는다.

## 검증 자료

최종 자동 결과·화면·문구 길이 표는 `.local/feedback-final-fixes/site/`와 `validation-summary.json`에 기록한다. 최초 실패 로그도 보존한다.

- Flutter analyze: 문제 없음. Flutter 전체 테스트: **357개 통과, 기존 제외 6개**.
- 제외 6개 중 웹 전용 업로드 3개(Blob 대체 처리·취소·결과 조회 오류)는 별도 Chrome 테스트로 재시도했으나 10분 이상 suite 로딩 단계에 머물렀다. 해당 테스트 브라우저만 종료했고 `Connection closed before test suite loaded`로 끝났다. 테스트 본문은 실행되지 않았으므로 **3개 미검증**이다. 나머지 3개는 기존 보류된 P0/원본 모드 토글 테스트이며 이번 작업에서 제외 정책을 바꾸지 않았다.
- 관련 백엔드 코칭·비교·API·새 비교 계약·모델 회귀 테스트: **199개 통과**. 격리 SQLite/FakeStorage를 사용했다. 저장된 EXP-005 NPZ는 읽기 전용으로 사용했으며 새 추론은 하지 않았다. 이는 관련 테스트 묶음이며 저장소의 모든 백엔드 테스트를 실행했다는 뜻은 아니다.
- 저장 리포트 및 합성 자료 18건을 실제 Flutter 매핑 코드로 재생했다. 원본 JSON 불변, 점수 스냅샷 동일, 유지된 근거의 z·품질·연습 조건 동일을 검사했다.
- Web release 빌드와 진단 앱 profile 빌드: 모두 성공.
- 실제 Chrome: 종합·관절·구간 및 펼침 상태 **31개 화면 캡처**, 짧은 구간·구/신 모델 단위·비교 불가·저신뢰/GPT 비승인 처리 **5개 화면 검증 통과**. 새 갤러리 15사례 전환, 원본 영상 재생, JSON/CSV 내보내기·복구, 430px 폭 표시를 확인했다. 갤러리 자동 저장 테스트는 합성 사례에만 수행하고 테스트 표식을 제거했다.
- 초기 pytest 임시 폴더 권한 오류는 이 작업 공간의 전용 임시 폴더로 해결했다. 기존 합성 비교 테스트는 검증된 계약을 명시하도록 갱신하고, 계약 없는 기록은 별도 거부 테스트로 검증했다.
- 초기 Web build는 Windows 셰이더 컴파일러의 상대 출력 경로 오류로 실패했다. 절대 출력 경로로 재실행해 성공했다. 추가 패키지 설치나 Flutter 버전 변경은 없다.

주요 로그는 `.local/feedback-final-fixes/`의 `backend-verified.log`, `flutter-tests-verified.log`, `analyze-verified.log`, `web-build-final.log`, `web-tests.log`, `browser-checks.json`, `gallery-validation.json`이다. 웹 테스트 로딩 실패와 실제 Chrome 화면 검증 성공은 별개로 기록했다. ## 사람 평가와 남은 검증

친구 영상 2개는 사용자가 직접 보고 문구 의견을 남겼다. 관절 정확성 판정 항목 7개 × 6영상은 여전히 전부 미검토다. 프로 4개는 자세 검토 미수행 상태를 유지한다. 자동 테스트나 화면 캡처를 사람 평가로 바꾸지 않는다.

서비스 반영 전에는 사용자 문구 재검토, 짧은 이벤트 경계의 독립 주석, 같은 계약으로 신규 분석 두 건을 저장하는 개발환경 E2E, Android 실기기 표시 확인이 필요하다. 실제 운영 Supabase, 신규 영상 추론, GPT 호출, 모델 학습은 이번 작업에서 수행하지 않았다.

- 정확한 변경 파일 목록은 최종 `changed-files.txt`에 저장한다. `.local` 검증 로그·영상·갤러리는 GitHub 반영 대상이 아니다.

마지막 원격 fetch에서도 origin/main은 `4e1ab160a90593eddcf462ead7aa7a96f9eebba3`였다. 새 worktree의 변경 29개 파일은 스테이징하지 않았다. 원본 간결화 worktree의 변경 5개와 기존 갤러리·평가 CSV 등 보호 대상 9개 파일의 SHA-256이 작업 전과 동일하다. 별도 모델 계산 파일의 diff는 없다.

갤러리를 재실행하려면 이 worktree에서 기존 Python으로 `.local/feedback-final-fixes/serve.py`를 실행한다. 서버는 `127.0.0.1:9020`에만 연결한다. 새 문구와 이전 문구는 갤러리 상단 영상 선택 후 종합·관절·구간 및 기본/펼침 선택으로 확인할 수 있다. 이 갤러리는 운영 서비스가 아닌 저장 결과 검토용이다.
