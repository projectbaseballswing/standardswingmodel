## 실제 자료와 결과

실제 저장 리포트와 원본이 연결된 6영상, 총 376프레임을 사용했다. 원본 SHA-256과 프레임 수를 확인했다. 4건은 `0.2-draft`, 친구 영상 2건은 `0.2.2-draft`이다. 최신 0.2.3으로 다시 추론한 결과는 아니다.

6영상 종합 카드의 기본 글자 수 합계는 **2,704 → 1,612자(40.4% 감소)**다. 제목·라벨·공백·줄바꿈을 포함한 Flutter Text 길이이다. 화면 전체 높이나 사용자 이해도 향상률이 아니다. 원문을 보존했으므로 펼친 뒤의 총량은 늘어난다.

기존 13개 Dart 출력의 점수·근거·후보 순위·긴 문구는 동일하다. 원본 6리포트의 후보 273개에서 수치·신뢰 조건·방향 코드의 일관성을 확인했다. 실제 야구 자세 정확성이나 교정 효과를 확인했다는 의미는 아니다.

## 발견한 기존 문제

1. 최신 손 높이 계산은 몸통 길이 기준인데 상세 한계 문구에는 어깨너비가 남아 있다. 앞발 높이는 모델 버전별 정의가 다른데 키만으로 최신 설명을 과거 기록에도 적용한다. 채택 전 버전별 설명 점검이 필요하다.
2. `/comparison`은 같은 계정의 이전 기록을 고르지만 모델·기준 해시·구간 가중치 호환성을 검사하지 않는다. Flutter는 종합·부위 이전 점수만 사용하며 관절·구간 변화값은 미표시다.
3. 저장 리포트 일부의 전환 구간은 1~2프레임이고, 원본과 구간 경계의 정합성에 의문이 있다. medium/high만으로 구간이나 교정을 승인할 수 없다.
4. 친구 영상 두 건에는 기준 곡선이 없다. 해당 원본만으로 기준 대비 차이를 직접 검증했다고 안내하면 안 된다.
5. 종합 부위 카드·관절·구간 간 관찰 문장 반복은 남아 있다. 이번 후보는 종합 카드의 기본 행동 안내를 줄인 범위다.

## 검토 자료

개인 영상과 로컬 검증 자료는 `.local/concise-review/`에만 있으며 Git 업로드 대상이 아니다.

- 갤러리: <http://127.0.0.1:9017/>
- 상세 보고서: <http://127.0.0.1:9017/report.html>
- 발표 요약·교수님 Q&A 5개: <http://127.0.0.1:9017/presentation.html>
- 전체 문구·함수·반복 위치: 갤러리의 ‘문장 전후’ 탭
- 원문 파일: `.local/concise-review/site/detailed-report.md`, `presentation-summary.md`

서버 재실행은 기존 Python 환경에서 `.local/concise-review/serve.py`를 실행한다. 기존 9017 서버가 살아 있으면 중복 실행하지 않는다. 서버는 `127.0.0.1`에만 바인딩하며 MP4 탐색용 HTTP byte range를 지원한다.
