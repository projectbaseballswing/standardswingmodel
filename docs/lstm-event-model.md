# LSTM: 예전 용도와 이번 용도

이 프로젝트에서 LSTM 은 두 번 쓰였다. 처음(0.1)에는 **기준 스윙을 고르는 데**, 이번에는 **스윙 이벤트 시점을 찾는 데** 쓴다.
같은 LSTM 이지만 학습 방식, 입력, 출력, 서비스에서 맡는 역할이 모두 다르다.

## 한눈에 비교

| | 예전 (0.1) LSTM 오토인코더 | 이번 LSTM 이벤트 판별 |
|---|---|---|
| 코드 | `modules/lstm/` (Colab 노트북에서 옮김) | `scripts/train_event_lstm.py`, `feedback/event_lstm.py` |
| 목적 | 프로 스윙 중 가장 "대표적인" 스윙 1개 고르기 | 영상에서 앞발 들기 / 착지 / 스윙 시작 / 임팩트 / 팔로우 끝 프레임 찾기 |
| 학습 방식 | 비지도. 정답 없이 입력을 그대로 복원하도록 학습 | 지도. 사람이 찍은 이벤트 라벨이 정답 |
| 입력 | 임팩트 기준 80프레임으로 자르고 DTW 로 맞춘 피처 | 영상 전체 프레임의 관절 좌표와 속도 (자르지 않음) |
| 출력 | 스윙 하나당 32차원 요약 벡터 | 프레임마다 "이 프레임이 각 이벤트일 확률" |
| 결과물 | 요약 벡터의 중앙값에 가장 가까운 스윙 1개 = 기준 스윙 | 이벤트 프레임 → 구간 나누기 → 프로 기준과 비교 |
| 서비스에서 | 기준 템플릿 만들 때 한 번 쓰고 끝 | 사용자 영상이 들어올 때마다 실행 |
| 정확도 확인 | 정답이 없어 잴 수 없었음 | 따로 떼어 둔 시험용 라벨로 규칙 감지기와 비교 |

## 예전 LSTM 오토인코더 (0.1)

1. 프로 스윙을 임팩트 기준 80프레임으로 자르고, DTW 로 시간축을 맞춘다.
2. 양방향 LSTM 이 80프레임을 32차원 벡터로 압축하고(인코더), 다시 80프레임으로 복원한다(디코더). 복원 오차를 줄이도록 학습한다.
3. 모든 스윙의 32차원 벡터를 구해 중앙값을 내고, 거기서 가장 가까운 실제 스윙 하나를 기준 스윙으로 고른다 (`find_nearest_real_swing`).

**그만 쓴 이유**

- 짧은 영상을 80프레임으로 맞추려고 첫 프레임을 복사해 채웠다. 모델이 이 복사 패턴까지 학습했을 가능성이 크다.
- DTW 가 시간축을 거의 맞추지 못했다 (스윙당 80프레임 중 평균 1.4프레임 보정). 사실상 임팩트 한 점만 맞춰진 상태였다.
- 결과가 "거리" 하나라서 "앞무릎이 너무 펴졌다"처럼 관절별로 설명할 수 없었다.
- 0.2 에서 이벤트로 구간을 나누고 프로 분포와 비교하는 방식으로 바꾸면서 기준 스윙 1개를 고를 필요가 없어졌다.

## 이번 LSTM 이벤트 판별

지금 이벤트는 규칙(손·발목 속도, 자세 템플릿)으로 찾는다. 라벨이 늘어도 정확도가 거의 오르지 않았다
(자세 템플릿 라벨 48개 → 166개: 임팩트 ±2프레임 65% → 67%, 스윙 시작 38% → 40%).
규칙은 라벨을 "배우지" 못하기 때문이다. 라벨을 그대로 학습하는 모델로 바꿔 이 한계를 넘는 것이 목표다.

**구조**

```
관절 좌표 (프레임별 12관절)
  → 골반 중심 원점, 몸통 길이 1 로 정규화, 프레임 간 속도 추가
  → 양방향 LSTM (앞뒤 프레임을 모두 보고 판단)
  → 프레임마다 이벤트 5개의 확률
  → 순서(앞발 들기 < 착지 < 스윙 시작 < 임팩트 < 팔로우 끝)를 지키는 프레임 선택
```

**학습 데이터**

- 사람 라벨: `data/labels.csv`. 시험용으로 떼어 둔 선수의 영상은 학습에 넣지 않는다.
- 라벨이 없는 영상(약 700개): 규칙 감지기 결과를 임시 정답으로 써서 먼저 학습(사전 학습)하고, 사람 라벨로 다시 맞춘다(미세 조정).

**시험 방법**

- 시험용 라벨은 앞발 들기가 영상에 남아 있는 스윙만 고르고, 선수 단위로 떼어 고정했다 (`data/event_test_split.json`).
  같은 선수의 다른 스윙이 학습에 섞이면 모델이 그 선수의 습관을 외워서 정확도가 부풀려진다.
- 라벨이 늘어도 시험지는 바꾸지 않는다. 그래야 "라벨을 더 해서 좋아졌는지"를 같은 기준으로 잴 수 있다.
- 규칙 감지기와 같은 시험지로 ±2프레임 이내 비율을 비교하고, 더 나은 이벤트에만 LSTM 을 쓴다.

**서버에서 실행**

API 서버에는 PyTorch 가 없다(`requirements-api.txt`). 학습은 PyTorch 로 하고, 학습한 가중치를 `.npz` 로 저장해 NumPy 로 계산한다.
모델 파일이 없으면 지금처럼 규칙 감지기만 쓴다.

## 결과 (2026-11-09, 라벨 188개)

**데이터 나누기**

- 시험: 선수 30명, 스윙 42개 (앞발 들기가 찍힌 라벨만. 시험용 선수의 영상은 학습에 전혀 쓰지 않음)
- 검증: 선수 17명, 스윙 27개 (어느 이벤트에 LSTM 을 쓸지 정하는 데 사용)
- 미세 조정: 사람 라벨 111개
- 사전 학습: 라벨 없는 영상 463개 (규칙 감지 결과를 임시 정답으로 사용)

**시험 결과** (±2프레임 이내 비율, 괄호는 평균 절대오차 프레임)

| | 앞발 들기 | 착지 | 스윙 시작 | 임팩트 | 팔로우 끝 |
|---|---|---|---|---|---|
| 규칙 감지기 | 69% (3.3) | 67% (3.2) | 55% (3.8) | 74% (3.2) | 45% (4.1) |
| LSTM 단독 | 67% (4.2) | **83% (1.6)** | **86% (1.4)** | **100% (0.7)** | 58% (2.7) |
| 서비스 적용 (규칙 + LSTM) | 69% | 83% | 86% | 100% | 45% |

- 시드를 바꿔 3번 학습해도 착지 81~83%, 스윙 시작 86~88%, 임팩트 93~100% 로 비슷했다.
- 검증 결과에 따라 착지, 스윙 시작, 임팩트에만 LSTM 을 쓴다. 앞발 들기는 규칙이 같거나 나았다.
  팔로우 끝은 시험에서는 LSTM 이 나았지만(58~74%) 검증에서 규칙이 나아서 이번에는 규칙을 쓴다. 검증 표본(27개)이 작아서 생긴 일로 보이며, 라벨이 늘면 다시 정한다.
- 서버 계산 시간: 영상 1개(116프레임)에 약 12ms (NumPy).

**기준 모델에 준 영향** (같은 프로 영상 890개)

| | 규칙 감지기 | 규칙 + LSTM |
|---|---|---|
| 기준 모델에 쓴 스윙 | 719개 | 801개 |
| 이벤트 순서가 어긋나 뺀 스윙 | 81개 | 9개 |
| '착지 후 준비' 구간 스윙 | 568개 | 775개 |
| 프로 종합 점수 하위 10% | 52점 | 60점 |

**다시 학습하기**

라벨이 늘면 `python scripts/train_event_lstm.py` 로 다시 학습하고 `python scripts/build_reference_model.py` 로 기준 모델을 다시 만든다.
시험지(`data/event_test_split.json`)는 바꾸지 않는다. `python scripts/eval_events.py --test-only` 와
`--test-only --rules-only` 로 같은 시험지에서 규칙과 비교할 수 있다.
